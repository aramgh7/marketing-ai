# Как креатив попадает в Meta: единственный путь через платформу

**Дата:** 2026-10-21 · **Статус:** решение принято, код — roadmap Phase 11 (не начат)
**Связано:** `.ai/landing-hosting.md` (где живёт лендинг), `.ai/meta-api-policy.md` §4, §6 (стадии записей), architecture §6 (клик → лендинг), §15.4/§16.17 (compliance, probe‑модерация)

---

## 1. Решение

**Креатив попадает в Meta только через платформу.** Кабинет загружает видео, создаёт креатив и объявление
на паузе через Marketing API, ставит адрес назначения с параметрами Meta и запоминает идентификатор
объявления. Объявление, созданное мимо платформы, считается **неуправляемым**: оно видно в кабинете, но
не участвует в обучении, в парах и в probe‑модерации.

Причина: ценность продукта — в измеримой связке «креатив → лендинг → путь воронки → результат». Связка
измерима только если в момент клика известен креатив. Если клиент скачивает файл и заливает его руками,
идентичность креатива теряется (переименование, перекодирование, забытые параметры в URL), и система
учится только на уровне лендинга. Это ровно та информация, ради которой платформа существует.

---

## 2. Что сейчас в коде и чего не хватает

| Есть | Нет |
|---|---|
| ML `/decide/landing` принимает `creative_id` в контексте решения | Edge middleware читает только `utm_source/medium/campaign`; идентификатор креатива из URL **не передаётся** |
| `creatives.meta_ad_set_id` — связь с набором объявлений, созданным платформой при запуске батча (`MetaCampaignService.createAdSet`) | Загрузки видео и создания объявления через API нет; объявление, созданное руками, с нашим креативом не сопоставляется |
| Probe‑модерация: вердикт читается по `effective_status` / `ad_review_feedback` (`ModerationProbeMath`) | Работает только для объявлений, которые платформа знает по id |
| Политика записей: `MetaWriteAction.LAUNCH`, стадии READ_ONLY → GUARDED_WRITES → FULL (`MetaWritePolicy`, V133) | Создание объявления **на паузе** не выделено как отдельный, самый безопасный класс записи |
| Скачивание файла: `GET /files/{tenant}/{creative}/{filename}` | Скачанный файл ничем не отличается от «опубликованного»; кабинет не показывает, что креатив не в Meta |

## 3. Как это работает после Phase 11

```
Кабинет: креатив (рендер монтажа, compliance PASS)
   │  кнопка «В Meta» (стадия ≥ GUARDED_WRITES, класс записи CREATE_AD_PAUSED)
   ▼
Marketing API: /advideos (chunked) → /adcreatives → /ads (status PAUSED)
   │  destination URL = https://{домен клиента}/l/{entry_slug}
   │  url_tags = mai_c={{ad.id}}&mai_p={{placement}}&mai_s={{site_source_name}}
   ▼
meta_ad_map: ad_id ↔ creative_id ↔ entry_slug ↔ ad_set / campaign
   │
   ├─ probe‑модерация читает вердикт по ad_id → ACTIVE из кабинета (RESUME) или кладбище (blocked_by_meta)
   │
   └─ клик: /l/{slug}?mai_c=123 → middleware → карта → creative_id → /decide/landing (контекст)
        → вариант лендинга → события → воронка → CAPI → награда плечу «креатив → лендинг → путь»
```

Сверка по чтению (READ_ONLY достаточно) идёт параллельно: раз в час платформа читает объявления аккаунта.
Объявление без строки в карте — «неуправляемое», алерт. Объявление, у которого руками изменили URL или
заменили видео, — «расхождение», алерт, плечо замораживается до решения человека.

## 4. Правила

1. **Один путь публикации.** Кнопка «В Meta» в кабинете. Ручная загрузка не запрещена технически (это Ads
   Manager клиента), но результат — неуправляемое объявление, и кабинет говорит это прямо.
2. **Скачивание ≠ публикация.** Для внешних клиентов скачивается превью с водяным знаком; финальный рендер
   уходит только кнопкой. Для нас самих (внутреннее использование) скачивание финала разрешено, но креатив
   получает статус `NOT_IN_META` и не участвует в обучении, пока не опубликован через платформу.
3. **Создание на паузе — отдельный класс записи** `CREATE_AD_PAUSED`: разрешён с GUARDED_WRITES, не требует
   FULL. Это самая безопасная запись: ничего не тратит и ничего не включает. Включение — `RESUME`, из
   кабинета, с записью в журнал решений. Массовые запуски и бюджеты остаются под прежними порогами.
4. **Динамические креативы и автоматические улучшения Meta выключены** для тестовых объявлений, иначе Meta
   сама перемешивает ролики и тексты и плечо перестаёт быть одним креативом. Для якорных — на усмотрение.
5. **Идентичность — наш креатив, не объявление.** Один креатив в нескольких объявлениях и плейсментах — одно
   плечо; плейсмент и источник (`{{placement}}`, `{{site_source_name}}`) — контекст решения, не новое плечо.
6. **Линковка — пункт онбординг‑чеклиста.** Пока у какого‑то активного объявления нет строки в карте или
   параметров в URL, запуск тестов заблокирован.
7. **Визиты без идентификатора креатива** (органика, рассылки) получают контекст «без креатива» и учат
   только лендинг. Это нормально, не ошибка.

---

## 5. Чего это не решает

- Не защищает аккаунт: защищают правила текста, одобренные фразы, стадии записей и probe‑модерация.
- Не делает креатив лучше: делает его измеримым.
- Не заменяет Automated Rules и Spending Limit в самом Meta — они остаются страховкой на стороне клиента.

---

## 6. Что потребуется от клиента

- Приложение платформы в его Business Manager с правом `ads_management` (уже в минимальном наборе scope).
- Page ID и, при необходимости, Instagram actor для объявлений.
- Перевод стадии в GUARDED_WRITES по существующим условиям (`MetaWriteStageService`): токен OK, CAPI‑события
  идут ≥ 14 дней, EMQ PASS, Automated Rules + Spending Limit подтверждены.
